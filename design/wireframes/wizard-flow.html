Decisions visible in these screens

  • The builds list is cards, not a table — each carries the one action that matters in its state: Continue, Watch progress, Retry that page, Open report.
  • Branches are picked before extraction, so a build always knows where it publishes and the review screen can name it.
  • A failed document is re-uploaded alone. The run does not restart — 5 pages is roughly 9 minutes of model time.
  • Nothing touches the tenant until Publish, and the review screen says so out loud.
  • The report counts the library too, because a build's second product is the entries the next venue will match against.
  • Re-publishing is safe — deterministic slugs update rows rather than duplicating them, which is what makes "publish now, add images in 4b" a real workflow rather than a rebuild.
