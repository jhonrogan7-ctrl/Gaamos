Expects: table_filter_options — list of {table, guests, total, selected, toggle_url} takeaway_available — bool (an open tableless session exists in scope) selected_takeaway — bool takeaway_toggle_url — str (current filter with the takeaway token flipped) active_filter_count — int clear_filter_url — str (current URL with ?tables= dropped, everything else kept) Rendered inside an x-data that exposes `filterOpen` (bool) and `tableQuery` (str). Alpine only shows/hides rows client-side as you type; the filter itself is applied server-side by following a row's toggle_url. On mobile `.table-filter` becomes a bottom sheet fixed over the queue and the nav. Because it is a sheet — and because it AUTO-OPENS whenever a filter is active — it must always carry a way out. Three of them: the grip, the Done button, and a tap outside. The footer is therefore never gated on `active_filter_count`; with no filter selected the Clear link is meaningless but Done is the only escape. {% endcomment %}
